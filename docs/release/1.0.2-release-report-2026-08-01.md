## Checkout and Apple Wallet decisions

- Android contains no usable merchant Checkout/pricing/billing path. The client requires `Platform.OS === "ios"` and the dedicated flag before invoking Checkout.
- iOS accepts only an HTTPS `checkout.stripe.com` URL. Missing business IDs, server rejection, network failure, and URL-open failure stay on localized approval-email and Contact Support guidance.
- Production migration `20260824150000_ios_trial_checkout_kill_switch.sql` is applied and the linked database reports no pending migration. The migration creates/upserts `ios_trial_checkout` as `enabled = false` with `launch_state = off`.
- `stripe-create-checkout-session` is deployed with the explicit `native_ios` source and refuses that source while the server switch is OFF.
- The Checkout capability is disclosed in Apple review notes, the public privacy policy, and the public business terms. It is described as remotely disabled at launch.
- Production Apple pass signing configuration is present by secret name: pass certificate, private key, WWDR certificate, pass type identifier, and Apple team identifier. Values were not displayed.
- `NATIVE_WALLET_PASS_ENABLED` is present and its stored digest matches `true`.
- `wallet-pass-issue` and `wallet-pass-webservice` were redeployed from the release source. The issue endpoint boots and rejects anonymous requests with 401; the PassKit `/v1/log` route responds 200.
- A real iPhone save/presentation remains an exact-binary QA gate; configuration and endpoint health do not substitute for PassKit device validation.

## Rollout, halt, and rollback

- Android: internal testing first, then staged production rollout; never immediate 100% availability.
- iOS: TestFlight first, then Apple phased release.
- Halt at the current rollout stage and pause Apple phased release if sign-in failures, crash rate, claim/redemption failures, or support volume regress against the 1.0.1 baseline.
- Monitor sign-in failures, merchant activation attempts, iOS Checkout failures if later enabled, first-deal publication, claims, redemptions, deletion, and support volume.
- For any iOS Checkout policy, review, or production issue: set `ios_trial_checkout` OFF immediately. If necessary, follow with a binary where the client flag is also false.
